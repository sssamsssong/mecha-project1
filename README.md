# Mechatronics Project 1 — PID Position Control & Auto-Tuning

DC 모터(엔코더 216 count/rev) 위치 제어용 PID 제어기를 C로 구현하고, step 응답을 평가해 게인을 반복 조정하는 자동 튜너를 Python으로 구현한다. (Raspberry Pi + wiringPi)

## 파일

| 파일 | 역할 | 수정 범위 |
|---|---|---|
| `AUTO_CONTROL_PROJ.c` | 모터 제어기 (10 ms 주기, CSV 로깅) | `positionControl()`만 |
| `AUTO_TUNE_PROJ.py` | 자동 튜너 (1분 이내) | `tune()`만 |
| `EVALUATOR.py` | 튜닝용 성능지표 | `evaluate()`만 |
| `PROJECT_SCORE.py` | 평가지표 A_k = ∫_{T-4}^{T} t·\|M(t)−r\| dt | 수정 금지 |
| `PLOT_GRAPH_PROJ.py` | CSV → HTML 응답 그래프 | 수정 금지 |

실행 인자, 엔코더 처리, CSV 형식, `run_motor()` 호출 방식은 유지한다.

## 빌드 / 실행 (Raspberry Pi)

```bash
gcc -o AUTO_CONTROL_PROJ AUTO_CONTROL_PROJ.c -lwiringPi
sudo ./AUTO_CONTROL_PROJ <목표위치(rev)> <실행시간(s)> 216 <P> <I> <D>
python3 PROJECT_SCORE.py <csv>
python3 AUTO_TUNE_PROJ.py
python3 PLOT_GRAPH_PROJ.py a.csv b.csv
```

## 구현 현황

모든 코드는 **배포 원본 상태**에서 Pi의 AI(opencode)로 하나씩 구현한다.

| 항목 | 상태 |
|---|---|
| PID 제어기 (`positionControl()`) | 조건부 적분 및 측정 위치 미분 필터 적용 (모터 미검증) |
| 응답 평가 (`EVALUATOR.evaluate()`) | 마지막 4초의 시간 가중 절대 오차를 목표 절댓값으로 정규화 |
| 자동 튜너 (`tune()`) | step 응답 지표 기반 상대 게인 탐색 |

PID는 10 ms 간격으로 계산한다. 출력이 ±100%를 넘는 방향의 적분은 중단하고 반대 방향 적분은 허용한다. D항은 목표 변화에 튀지 않도록 측정 위치를 미분하고, 계수 0.2의 저역통과 필터로 엔코더 계단 잡음을 줄인다. PWM은 원본 P 제어와 같이 소수점을 버린다. 이는 현재 `AGENTS.md`의 반올림 규칙과 다르며, 사용자 요청에 따른 것이다.

자동 튜닝은 `python3 AUTO_TUNE_PROJ.py [P I D]`로 초기 게인을 지정한다. 인자가 없으면 배포 예제 기본값 `[10, 0, 0]`으로 시작하며, 지정한 유한·비음수 초기 게인은 첫 측정에 그대로 사용한다. 이후에는 현재·최고 게인과 step 응답 지표로 상대 변경한다. 점수 차이 ±3% 미만은 동등, 최고 게인 재측정은 점수 평균, 실패 조합의 모든 축 ±10% 이내는 재탐색 제외다. 새 후보는 기존 발산 방지 상한 `1e6`을 적용하되 최고 게인 복귀값은 그대로 둔다. 현재 버전의 D 증가 실패 후 I/D 감소 탐색은 유지했고, 새로운 이른 제동 진단(규칙 8/9)은 이번 안전 개선에 포함하지 않았다.

무동작 응답은 최고 갱신·평균·실패 목록에서 제외한다. 한 카운트 D 출력 경계 `100*216*0.01/0.2`, 초기 오차에서 적분 한 걸음 포화 경계 `100/(|목표|*0.01)`를 넘으면 D/I를 먼저 줄인다. P 부족이면 초기 오차(최소 한 카운트)와 응답 심각도 배율 `steps[0]`로 P를 늘린다. **고정 8배가 아니라 최대 32배**이며, 무동작 P 후보는 한 카운트 오차의 출력 포화 경계 `100*216` 이내로 제한한다. 첫 `[0,0,0]` 측정은 무동작 횟수에서 제외하고 그 응답으로 P를 시작한다. 무동작 2회 연속 또는 목표 절댓값 2배 초과 위치 이탈은 중단한다. 이전에 움직인 적이 있고 응답 전체가 갑자기 0이면 같은 게인으로 한 번 재측정하며, 재시도도 무동작이면 중단한다. 이 재측정은 후보 상한·실패 근접 우회로 게인을 바꾸지 않는다.

CSV/실행 오류와 `run_motor()`의 `SystemExit`는 튜너 내부에서 기록 후 종료하고 `Final gains:`를 출력한다. 유효한 움직임 응답이 없으면 초기 게인과 평가 불가 점수(`inf`)를 반환한다. 사용법 오류는 기존대로 종료하며, `Ctrl+C`·파일 기록 오류 등 모든 외부 중단까지 최종 출력을 보장하지는 않는다. 검사는 측정 종료 후이므로 구동 중 안전장치가 아니다. 매 실행 전 5초 구동·1초 대기·실측 오버헤드·여유 시간을 고려하지만 기존 실행/그래프의 지연 때문에 전체 60초는 절대 보장되지 않는다. 과정은 `results/tuning_*.csv`에 원래 형식으로 기록한다.

모터 없는 검사: `python3 check_tuning.py --self-test`는 AST로 `_tuning_` 함수만 추출해 검사한다(튜너 import 금지). `python3 check_tuning.py results/tuning_XXXX.csv [터미널로그]`는 회차 표와 P/I 포화 경계 초과 후보, 60초 초과, 동일 게인 연속 실패, 최종 출력 누락을 확인한다. 경계 경고에는 최고 게인 복귀도 포함되므로 곧바로 규칙 위반을 뜻하지는 않는다.

## Pi 준비

- 엔코더 A/B 선(GPIO17, 27)에 3.3 V 풀업 저항 2개가 꽂혀 있어야 한다(실습 6 p.16). 없으면 encPos가 0에서 안 변하고 모터가 멈추지 않는다.
- 실행은 터미널에서 `sudo`로 하고, 종료는 `Ctrl+C`로 한다. 모터가 안 멈추면 `pinctrl set 19 op dl; pinctrl set 26 op dl`.

### 출력축 1바퀴 수동 계수 확인

`encoder_check.c`는 GPIO17/27의 양쪽 에지를 읽으며 모터 출력 핀은 건드리지 않는다. 기존 제어 코드와 환산값 216은 그대로 유지한다. A/B 상태 전이로 계수하고 콜백을 잠금으로 보호하므로 기존 ISR과 구현은 다르며, 기존 ISR의 동작을 완전히 검증하는 도구는 아니다.

```bash
gcc -Wall -o encoder_check.out encoder_check.c -lwiringPi
sudo ./encoder_check.out
```

다른 모터 제어 프로그램을 종료하고 모터 구동 전원은 끈다(엔코더 전원과 외부 풀업은 유지). 축이 정지한 상태에서 실행하고, 출력축을 한 방향으로 천천히 정확히 1바퀴 돌린 후 `Ctrl+C`로 종료한다. 감속기 축은 억지로 돌리지 않는다. 출력되는 순카운트 절댓값이 관측된 1바퀴당 계수이며, `count/216`은 기존 환산값으로 읽힌 위치다. 입력 잡음이나 신호 누락이 있으면 이 계수도 부정확하므로 A/B 인터럽트 수와 두 비트 동시변화를 함께 확인한다.

## 조건

- 제어 주기 10 ms, 1회 실행 ≤ 10 s (A_k 평가는 5 ≤ T ≤ 10)
- 자동 튜닝: PID + step 위치 응답만 사용, 1분 이내, 튜닝 과정(게인·평가값) CSV 기록, 종료 시 최종 게인 출력
- 2번째 이후 게인은 반드시 튜닝 알고리즘이 결정

## 결과 보관

실행 CSV/HTML은 작업 폴더에서는 git에 안 올라간다. 보고서·제출용으로 남길 것만 `results/` 아래로 옮겨 커밋한다.

측정 결과를 `runs/`로 자동 정리하려면 다음을 사용한다. 두 명령 모두 실제 모터를 구동한다.

```bash
./run.sh <목표위치(rev)> <실행시간(s)> 216 <P> <I> <D>
./tune.sh
```

`run.sh`는 점수 출력 후 해당 CSV를 옮긴다. `tune.sh`는 그래프 생성까지 종료된 뒤 루트의 CSV와 HTML을 모두 옮긴다. 같은 이름이 있으면 번호를 붙여 보존한다. `runs/`는 git 무시 대상이 아니므로 커밋할 파일을 확인한다.

기존 CSV 비교: `python3 compare.py runs/*.csv` (모터 실행 없음). 새 점수는 `A_k / |목표|`이며, 4초 미만 기록은 기록된 구간만 사용하고 목표 0은 1로 나눈다. 같은 목표 절댓값의 유효한 기록은 실제 점수와 순서가 같다. 목표 크기가 다르면 실제 점수와 순서가 다를 수 있다.

같은 PID의 실제 점수 나열: `./score_pid.py <P> <I> <D>` (예: `./score_pid.py 200 100 4`). `runs/`의 CSV에서 게인을 확인하며 모터는 실행하지 않는다. 목표와 실행 시간이 같은 결과끼리 비교한다.

상승시간은 목표의 10%에서 90%까지, 정착시간은 이후 끝까지 목표 ±2%를 유지하는 최초 시각이다. 오버슈트는 목표 방향 최대 초과율, 정상오차는 마지막 0.5초의 평균 절대 오차(rev)다. 진동 횡단은 ±2% 바깥 양쪽을 번갈아 통과한 횟수(반 주기 단위)이며, 움직임은 위치 범위가 `max(0.001 rev, 목표 절댓값의 1%)`를 넘는지로 판정한다. 미도달 값은 `-`로 표시한다.

## 수동 스윕

다음 명령은 실제 모터를 구동한다. 단계별 결과를 확인하고 다음 조합은 직접 선택한다.

```bash
./sweep.sh 1                          # P 50,100,200,400 × D 0,2,4,8; I=0 (16회)
./sweep.sh 2 <P1> <D1> <P2> <D2>     # 각 조합에 I 0,50,100,200
./sweep.sh 3 <P1> <I1> <D1> <P2> <I2> <D2> [P3 I3 D3]  # 각 3회
python3 analyze_sweep.py              # 기존 runs/*.csv 분석, 모터 실행 없음
```

기본 목표는 10 rev, 시간은 5초이며, `--target -3 --time 10`처럼 단계 앞에 지정할 수 있다. `3a`는 조합마다 3회, `3b`는 2회 반복한다. 실행 후 1초 쉬고 CSV 누락, 기록 오류 또는 위치 변화가 없는 경우 즉시 중단한다. 이는 매 측정 종료 후 검사하므로 구동 중 이상을 감지하는 안전장치는 아니다. 새 목록 `runs/sweep_manifest_v2.tsv`에 목표·시간을 포함해 기록하며 기존 `sweep_manifest.tsv`도 그대로 읽는다. 중단·실패·이상 기록은 분석에서 제외하고 목록이 없는 CSV는 미분류로 집계한다. 분석은 목표·시간별로 나누고 A_k와 A_k/|목표|를 함께 표시한다. 실행 시간이 다르면 A_k/|목표|도 시간 가중치가 달라 직접적인 동등 비교는 아니다. 정착시간은 정착한 실행만 집계한다. 1단계 후보는 A_k 차이가 0.1 미만인 그룹을 비슷하게 보고 오버슈트, 진동 횡단 순으로 정렬한다. 최종 선택은 사용자가 한다.

직접 작성한 반복문에서 `run.sh`의 중단/실패 후 확실히 멈추려면 `./run.sh ... || break`를 사용한다.
